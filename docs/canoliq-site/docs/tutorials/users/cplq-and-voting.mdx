# Claim, stake, and vote with CPLQ

**Goal.** Turn a CPLQ allocation into voting power and cast a vote.

CPLQ is the governance token. Fixed supply, 100,000,000, none minted after
genesis. Holding it does nothing on its own: you must **stake** it to get
voting weight.

## 1. Claim vested CPLQ

Genesis allocations unlock on a schedule. Check yours:

```bash
curl -s localhost:8587/v1/vesting/<your-address>
```

```json
{
  "address": "<your-address>",
  "schedules": [
    {
      "schedule": {"scheduleId": 0, "totalAmount": 10000000000, "cliffHeight": 50000, "claimedAmount": 0},
      "unlockedToDate": 3000000000,
      "claimableNow": 3000000000,
      "currentHeight": 200000
    }
  ]
}
```

`claimableNow` is what you can take today. A `404` means you have no schedule.

```bash
canoliqctl cplq-claim-vested <your-address>
```

This claims everything currently unlocked across all your schedules. Nothing
happens before the cliff height.

## 2. Stake, and choose a lock tier

```bash
canoliqctl cplq-stake <your-address> 1000000000 --lock 12m
```

That stakes 1,000 CPLQ locked for 12 months. The lock multiplies your voting
weight:

| `--lock` | Voting multiplier | Reward boost |
|---|---|---|
| `none` | 1× | base |
| `3m` | 1.5× | +10% |
| `6m` | 2× | +25% |
| `12m` | 3× | +50% |
| `24m` | 4× | +75% |

1,000 CPLQ at `12m` votes as 3,000. The minimum to *create* a proposal is 1
CPLQ staked.

:::caution A lock cannot be shortened
Choosing `24m` commits the stake for roughly two years. You cannot unstake, and
there is no early exit. Pick the term you can live with.
:::

## 3. Understand the snapshot rule before you vote

Voting weight is taken from when you **staked**, not when you vote:

- Your weight is your stake as of the proposal's `creation_height`.
- A vote is rejected if your `stakedAtHeight` is later than that.

This defeats flash-stake attacks, and it has a consequence that surprises
people:

:::caution Adding stake forfeits your vote on open proposals
Increasing your stake resets `stakedAtHeight` to now, which is later than any
already-open proposal's creation height. You lose eligibility on every
proposal currently in flight. Vote first, then add stake.
:::

## 4. Find a proposal and vote

```bash
curl -s localhost:8587/v1/proposals
curl -s localhost:8587/v1/proposal/1
```

```bash
canoliqctl vote <your-address> 1 yes
```

Choices are `yes`, `no`, or `abstain`. Abstain counts toward quorum but not
toward the approval threshold.

## 5. Confirm it landed

```bash
curl -s localhost:8587/v1/vote/1/<your-address>
```

## What bar does the proposal need to clear?

Different actions clear different bars, and the headline 33% quorum figure is
only a fallback for actions with no tier:

| Action | Quorum | Approval | Timelock |
|---|---|---|---|
| Fee change | 5% | 51% | 48h |
| Treasury spend (small) | 5% | 51% | 48h |
| Treasury spend (large) | 10% | 67% | 7d |
| Emergency | 8% | 67% | none, 24h vote |
| Validator ejection | 5% | 51% | 48h |
| Protocol upgrade | 10% | 67% | 7d |
| Autonomy graduation | 15% | 75% | 14d |
| OTC program funding | 10% | 67% | none |

See [Governance tiers](../../governance/governance-tiers.mdx) for the full rules.

## Troubleshooting

| Message | Code | Meaning |
|---|---|---|
| `insufficient liquid CPLQ balance` | 104 | Stake more than you hold. Claim vested CPLQ first |
| `no vested CPLQ available to claim` | — | Nothing unlocked yet; you are before the cliff |
| `no vesting schedule for address` | — | This address has no allocation |
| `voter stake added after proposal creation height` | — | You staked after the proposal opened. See the snapshot rule above |
| `address has already voted on this proposal` | — | One vote per address per proposal |
| `proposal not in active voting window` | — | Voting has closed, or has not opened |
| `stake is locked until lock_end_height` | — | Unstaking before the vote-escrow term ends |
| `proposer staked CPLQ below minimum` | — | Below `min_stake_to_propose` |

## Unstaking

```bash
canoliqctl cplq-unstake <your-address> 1000000000
canoliqctl cplq-claim-unstake <your-address> <unstake-id>
```

Like redemption, this is two steps with a wait between. The window is about
seven days and is never shorter than the voting period, so a vote cannot be
cast and then unwound before it is counted. Find the id and `matureHeight`
under `unstakes` on `/v1/account/{addr}`.
