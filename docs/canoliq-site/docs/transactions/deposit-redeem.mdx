# Deposit & Redeem Flow

:::tip Looking for the walkthrough?
This page is the reference: what each message does to state. For step-by-step
instructions with verification, see
[Deposit](../tutorials/users/deposit.mdx) and [Redeem](../tutorials/users/redeem.mdx).
:::

## Deposit CNPY → Mint cCNPY

Users deposit CNPY into the canoLiq pool and receive cCNPY at the current exchange rate.

```bash
canoliqctl deposit <address> <amount_uCNPY>
```

**Effect**:
1. CNPY is debited from the user's Canopy `Account`
2. cCNPY is minted to the user's canoLiq balance:
   `ccnpyMinted = depositAmount × (totalCCNPYSupply + 1) / (totalPooledCNPY + 1)`
   The `+ 1` on each side is a virtual offset that keeps a fresh or emptied pool
   from dividing by zero and from being rate-manipulated. On the first deposit
   into an empty pool the rate is therefore 1:1.
3. The deposited CNPY moves into the escrow pool that backs cCNPY, and
   `CanoliqGlobals.totalPooledCNPY` / `totalCCNPYSupply` are updated
4. A flat transaction fee (`deposit_fee`, 10,000 uCNPY by default) is charged
   **on top of** the deposit and routed to the committee fee pool

:::note The 12% protocol fee is not charged here
The 12% fee and its 40/30/15/15 split apply to staking **rewards** the protocol
receives, not to deposits. Depositing 10 CNPY pools the full 10 CNPY; only the
flat transaction fee is extra. See [Fee structure](../tokenomics/fee-structure.mdx).
:::

## Redeem cCNPY → Queue CNPY

Users burn cCNPY and queue a CNPY redemption that matures after the validator unstaking window.

```bash
canoliqctl redeem <address> <amount_uCCNPY>
```

**Effect**:
1. cCNPY is burned from the user's balance
2. CNPY owed is computed at the current rate, with the same virtual offset as
   minting: `cnpyOwed = ccnpyAmount × (totalPooledCNPY + 1) / (totalCCNPYSupply + 1)`.
   The result floors, so a few uCNPY of dust stays with the pool.
3. A `Redemption` record is created with:
   - `cnpy_amount`: CNPY owed at maturity
   - `unbond_complete_height`: current height + `redemptionUnstakingBlocks`
4. `CanoliqGlobals.pendingRedemptionCNPY` is incremented and `totalPooledCNPY`
   is decremented: the amount is fixed at redemption time and stops earning
5. `CanoliqGlobals.nextRedemptionId` is incremented

## Claim Matured Redemption

After the unbond period, users claim their CNPY.

```bash
canoliqctl claim <address> <redemption_id>
```

**Effect**:
1. Validates the redemption exists and has matured (`current_height >= unbond_complete_height`)
2. CNPY is credited to the user's Canopy `Account`
3. `CanoliqGlobals.pendingRedemptionCNPY` is decremented
4. The redemption record is deleted

## Worked Example

```bash
export CANOLIQCTL_PASSWORD=hunter2

# Deposit 1 CNPY (1,000,000 uCNPY)
./canoliqctl deposit 851e90eaef1fa27debaee2c2591503bdeec1d123 1000000

# Redeem 0.25 cCNPY (250,000 uCCNPY)
./canoliqctl redeem 851e90eaef1fa27debaee2c2591503bdeec1d123 250000

# After unstaking window (~UnstakingBlocks blocks)
./canoliqctl claim 851e90eaef1fa27debaee2c2591503bdeec1d123 0
```
